# AI 변경 승인 게이트

TIL 생성은 모델, 프롬프트 버전, 출력 스키마 버전을 하나의 변경 단위로 묶습니다. 실행 시점에 이 세 값과 정확히 일치하는 승인 레코드가 없으면 외부 모델을 호출하지 않습니다.

승인 레코드는 `app/core/ai_release.py`의 `AI_RELEASES`에 있으며 상태는 `pending`, `approved`, `rejected` 중 하나입니다. 프롬프트나 응답 스키마를 변경할 때는 다음 순서를 따릅니다.

1. `TIL_AI_CONTRACT`의 해당 버전을 올립니다.
2. 새 `release_id`로 레코드를 추가하고 상태를 `pending`으로 둡니다.
3. 계약 테스트와 품질 평가를 통과한 뒤 해당 레코드만 `approved`로 전환합니다.
4. 이전 레코드는 유지해 변경 이력을 코드 리뷰에서 추적할 수 있게 합니다.

현재 게이트는 TIL 생성 경로에만 적용됩니다. 승인 정보는 소스 코드에 저장되며 관리자 화면, 다중 승인 및 자동 롤백은 아직 제공하지 않습니다.

## 출력 계약 검증

TIL 생성 모델의 JSON 응답은 `til-response-v1` 계약으로 실행 중 검증합니다. 응답은 `title`과 `til_markdown` 두 문자열 필드만 가져야 하며, 제목은 비어 있지 않은 한 줄이어야 하고 마크다운은 `# TIL` 1단계 헤더로 시작해야 합니다. 추가 필드, 타입 변환이 필요한 값, 빈 값, 잘못된 헤더는 모두 거부합니다.

계약 위반 결과는 임베딩에 전달하거나 API로 반환하지 않고 결과 캐시에도 저장하지 않습니다. 실행 감사에는 원문이나 잘못된 모델 출력 대신 `til_output_contract_violation` 오류 코드만 실패 상태로 기록합니다.

## 실행 감사 기록

캐시에 없는 TIL 생성은 승인된 릴리스 정보, 입력 건수, 시작·완료 시각, 성공·실패 상태와 오류 코드만 SQLite에 저장합니다. 프롬프트와 원문은 저장하지 않습니다. 감사 기록 시작 또는 완료에 실패하면 추적 불가능한 AI 실행을 허용하지 않고 요청을 중단합니다.

저장 경로는 `AI_AUDIT_DB_PATH`로 지정합니다. 기본값은 로컬 실행용 `/tmp/san-ai-execution-audit.sqlite3`이므로 컨테이너 교체 후에도 보존해야 하는 환경에서는 영속 볼륨 경로로 반드시 변경해야 합니다. 현재 기록은 단일 SQLite 파일 기준이며 다중 인스턴스 공유 저장소, 조회 API와 보존 기간 자동 삭제는 제공하지 않습니다.
